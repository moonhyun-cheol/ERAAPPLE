# AutoEtd 1.0.3 — 현재 이벤트 연결 지도

## 조사 범위와 결론

대상: `放置系エロトラップダンジョン ver1.0.3/放置系エロトラップダンジョン ver1.0.3`.

이번에는 `AutoEtd.data`를 SQLite 읽기 전용으로 조회하고, `AutoEtd.Core.dll`과 `AutoEtd.exe`를 ILSpyCmd 9.1.0.7988로 정적 분석했다. 게임을 실행하거나 원본을 수정하지 않았다. 디컴파일 결과는 OS 임시 폴더에만 두며 이 문서에 원문 장면이나 전체 코드를 복제하지 않는다.

**핵심: 고정된 이야기 트리라기보다, 던전 해금 사슬 + 탐험 상태 머신 + 상태에 반응하는 거점 분기 + 재사용 행동/문구 데이터의 조합이다.** 전역 흐름과 주요 연결 지점을 확인했으며, 모든 상태 조합의 실제 플레이 도달 가능성을 전수 검증했다는 뜻은 아니다.

동반 자료: [비서술형 DB 연결 자료](autoetd-event-links.json). `calls`는 참조 발생 지점 목록이지 실행 순서가 아니며 같은 출발·도착 ID가 중복될 수 있다. 본문 수치는 이 배포본 기준이다.

## 1. 전체 흐름

```text
거점 → 던전 선택 → 탐험 시작
                       │
                       ├─ 영구 상태의 시작 효과 적용
                       └─ 탐색 루프
                            ├─ 작전 행동이 있으면 실행 → 다음 턴
                            ├─ 진행 가능 → 사건 생성
                            │    ├─ 아무것도 없음 ───────────┐
                            │    ├─ 보물상자 → 장비 획득 ────┤
                            │    ├─ 함정 → 즉시 효과/지속 상태┤
                            │    ├─ 적 → 전투 → 승리 ────────┤
                            │    └─ 계단                     │
                            │         ├─ 중간 층 → 층+1 ─────┤
                            │         └─ 마지막 층 → 마지막 전투
                            │                          ├─ 승리 → 탐험 성공
                            │                          └─ 패배 → 탐험 실패
                            └─ 행동 불가 → 상태 처리         │
                                 └─ 조건부 추가 적 조우      │
                                      ↑_____________________┘

성공 / 실패 / 수동 중단
    ├─ 자동 주회가 계속되면 회복·일반 상태 정리 후 다시 탐험
    └─ 탐험 화면에서 귀환 → 결과 화면 → 거점 화면 진입
                                               ↓
                                       거점 이벤트 조건 판정
                                       ├─ 이벤트 없음
                                       ├─ 귀환 과정
                                       ├─ 광장 + 군중
                                       └─ 자실 휴식
                                               ↓
                                       종료 또는 화면 이동
                                               ↓
                         거점 화면 이탈 시 Refresh → 다음 활동
                         (일반 상태 제거, 영구 상태는 유지)
```

주의: 성공/실패가 즉시 다른 화면으로 자동 이동한다는 뜻이 아니다. 탐험 화면의 귀환 처리에서 결과 화면으로 이동하며, 결과 화면에서 돌아올 때 거점으로 이동한다. 자동 주회 사이에는 거점 이벤트 엔진을 호출하지 않는다.

## 2. 던전 해금: 실제로 일직선인 부분

```text
제1층 클리어
  → 제2층 클리어
    → 제3층 클리어
      → 제4층 클리어
        → 제5층 클리어
          → 심층 [성공 또는 실패 기록]
            → 커스텀 던전 사용 가능
```

| 구역 | DB ID | 내부 층 범위 | 선행 클리어 | 적 그룹 등록 수 | 직접 함정 등록 수 |
|---|---:|---|---|---:|---:|
| 제1층 | 1 | 1–5F | 없음 | 7 | 5 |
| 제2층 | 3 | 1–7F | 제1층 | 7 | 8 |
| 제3층 | 4 | 1–7F | 제2층 | 7 | 12 |
| 제4층 | 2 | 1–7F | 제3층 | 7 | 11 |
| 제5층 | 7 | 1–8F | 제4층 | 7 | 10 |
| 심층 | 9 | 1F | 제5층 | 1 | 0 |

- `Dungeons.NeedClear`는 던전 이름으로 연결된다. 코드에서는 선행 던전의 `SuccessCount > 0`을 검사한다.
- **정정:** 커스텀 해금은 심층 클리어만 요구하지 않는다. 심층이 탐험 가능하고 그 `SuccessCount > 0` 또는 `FailureCount > 0`이면 열린다. 단순 진입·수동 중단 기록만으로는 이 조건을 충족하지 않는다.
- 마지막 전투도 `GenerateEnemyParty()`로 해당 던전의 일반 적 그룹 풀에서 고른다. 현재 여섯 던전의 `BossEnemyGroupId`는 모두 NULL이다. 이름에 `Boss`가 있다고 별도 보스 시나리오를 뜻하지 않는다.
- 심층에서는 일반 사건 생성기가 `NextFloor`를 반환하므로 일반 진행 시 마지막 전투로 연결된다. 그보다 먼저 처리되는 상태의 진행 훅은 별개다. 심층 자동 주회는 코드에서 비활성화한다.

## 3. 탐험 사건: 독립 확률 추첨이 아니라 진행 카운터

탐험의 매 턴이 아니라, 실제 `Progress()`가 호출되는 때 사건 생성이 진행된다. 비전투 회복·강화 작전이나 행동 불가 상태 때문에 진행하지 않는 턴도 있다.

| 사건 | 첫 기준값 | 재발 기준값 | 비고 |
|---|---:|---:|---|
| 계단 | 13 | 13 | 마지막 층이면 마지막 전투 |
| 몬스터 | 3 | 6 | 던전의 적 그룹 풀 사용 |
| 함정 | 3 | 6 | 던전의 함정 풀 사용 |
| 보물상자 | 8 | 8 | 장비 생성 후 탐색 계속 |

내부적으로 기준값을 10배 하여 보관하고, 기본 진행량 10에 ±50% 변동을 주어 차감한다. 따라서 “정확히 3턴마다 함정”이라는 뜻이 아니다. 동시에 준비된 사건이 있으면 **계단 → 몬스터 → 함정 → 보물상자** 순서에서 첫 사건 하나를 선택하고, 선택된 사건의 카운터만 재설정한다.

- `AvoidMonster`, `AvoidTrap`: 해당 진행량을 기본 10에서 5로 줄인다.
- `SearchTreasure`: 보물 진행량을 10에서 20으로 늘린다.
- `誘引洗脳` 상태: 탐색 진행 시 상태 레벨×3%로 몬스터/함정 중 하나를 우선 발생시킨다. 일반 사건 생성보다 먼저 판정하고 해당 사건 카운터를 초기화한다.

### 함정에서 전투로 이어지는 경로

```text
함정 선택
  ├─ IsRestrain=false → 행동 패턴에서 명령 하나 실행 → 탐색 계속
  └─ IsRestrain=true → TrapRestraint 상태 부여
                         ├─ 행동 전 함정 패턴 실행
                         ├─ 저항/지속 시간 등 상태 처리
                         └─ 행동 불가 처리 중 추가 조우 조건 확인
                               ├─ 허용 → 20% 판정 → 적 그룹 생성 → 전투
                               └─ 불허 → 기존 상태 처리 계속
```

20%는 모든 함정에 무조건 적용되는 확률이 아니다. `CanAction/CanAvoid`와 `JudgeCanAction`의 해당 분기에 들어가고, 현재 `TrapRestraint`가 없거나 그 함정의 `CanBattle`이 참이어야 한다. 실제 적 파티가 생성되면 몬스터 사건 카운터를 초기화한다. 구속 함정의 초기 지속 시간은 DB `MaxTurn`에서 가져온다.

HP가 0이면 탐험자에게 다운 상태를 부여한다. VP에 해당하는 코드 속성은 `Sanity`이며, 0일 때 전투불능 처리로 이어진다. **HP 0과 탐험 실패를 같은 사건으로 보면 안 된다.**

## 4. 거점 이벤트: 가장 뚜렷한 조건 분기

생성 시점은 `HomeViewModel.OnNavigatedTo`, 즉 거점 화면에 들어올 때다. 탐험 성공 여부만이 아니라 **그때의 VP와 상태 레벨**이 선택을 결정한다.

다음 두 내부 상태를 A/B로 표기한다. 원문 식별자는 각각 `発情` / `おあずけ`다. 이는 코드와 대조하기 위한 명칭이며 장면 내용은 생략한다.

```text
거점 진입
  │
  ├─ [우선 조건] A 레벨≥20 또는 B 레벨≥20 ?
  │      ├─ 예 + VP=0 → ReturnEvent (귀환 과정)
  │      └─ 예 + VP>0 → RestInMyRoomEvent (자실 휴식)
  │
  └─ 위 조건 아님
         ├─ VP>0 → 이벤트 없음
         └─ VP=0
              ├─ 50% 판정 실패 → 이벤트 없음
              └─ 50% 판정 성공
                    → CanExecute를 통과한 후보 중 하나 무작위 선택
                       ├─ ReturnEvent
                       ├─ CompositeEvent(CrucifyEvent, CrowdEvent)
                       └─ RestInMyRoomEvent [추가 조건 필요]
```

세부 사항:

- 우선 조건 경로는 50% 판정과 일반 후보의 `CanExecute` 검사를 거치지 않는다.
- 일반 후보의 자실 이벤트는 `EventData`에 지정된 8개 상태 기반 값의 합계가 20 이상일 때만 선택 대상이다. 일부 값은 신체 설정·다른 상태 보유 조건도 검사한다.
- 우선 조건이 아닌 VP=0 경로에서 후보가 두 개이면 각각 전체 판정의 25%, 세 개이면 각각 약 16.7%다. 이벤트가 없는 50%는 별도로 남는다.
- 이 수치는 현재 선택 코드에서 계산한 값이다. 실기 반복 측정 확률은 아니다.

### 선택 후 진행과 종료

| 이벤트 | 시작 처리 요약 | 진행·정상 종료 조건 |
|---|---|---|
| 귀환 과정 `ReturnEvent` | 일부 구속/다운 상태 정리, HP/MP=0, VP=최대의 절반, 특정 일시 상태 부여 | 실제 이동에 성공한 횟수 20회. 일반 작전 행동을 하면 그 턴에는 이동 대신 행동 |
| 광장 `CrucifyEvent + CrowdEvent` | 일부 상태 정리, HP/MP 회복, VP=최대의 절반, 지정 함정 구속 부여 | 행동·회피 가능하고 행동 판정에 성공하면 종료 |
| 자실 `RestInMyRoomEvent` | VP=0이면 Refresh 후 탐험 시작 훅 호출, 그 외에는 일부 상태 정리와 HP/MP 회복 | 실제 휴식 성공 30회. 행동이 방해된 턴은 횟수를 줄이지 않음 |

공통적으로 파티 전멸 판정이면 실패 종료하며, 화면 이동 요청에서는 실행을 취소한다. 귀환 이동 방해 확률은 `clamp((군중 수 - 5) × 5, 0, 50)%`다. 군중은 캐릭터의 상태와 수치에 반응해 늘어나고 별도의 DB 행동 패턴을 호출한다.

**중요: 광장 → 귀환 → 자실이라는 연속 시나리오가 아니다.** 셋 중 선택된 하나를 실행한다. 귀환에는 군중 로직이 내부 구성으로 포함되며, 광장은 광장 로직과 군중 로직을 함께 돌리는 복합 이벤트다. `CompositeEvent`는 두 장면을 차례로 보는 의미가 아니다. 같은 이벤트의 턴 단계마다 구성요소를 호출한다.

현재 엔진은 한 이벤트가 끝났다고 다음 거점 이벤트를 자동으로 새로 선택하지 않는다. 거점 화면에서 나갈 때 `Refresh()`가 HP/MP/VP를 회복시키고 일반 상태를 제거하지만 영구 상태는 보존한다.

## 5. 적·함정·상태의 실제 연결 구조

```text
Dungeons
  ├─ DungeonEnemyGroups → EnemyGroups → EnemyGroupMembers → EnemyClasses
  │                                                        └─ ActionPatterns
  └─ DungeonTraps → TrapClasses ────────────────────────────→ ActionPatterns
                                                              ↓
                                              위에서부터 조건·대상 검사
                                              실행 가능한 첫 패턴 선택
                                                              ↓
                                          가능한 행동/대상 명령 중 하나 선택
                                              ├─ 직접 행동과 상태 변화
                                              ├─ CallEntity → BattleActions
                                              └─ CallEnemy → EnemyClasses → 적 추가
```

- 패턴의 여러 `Conditions`는 대상 집합의 교집합으로 적용된다.
- `Actions` 배열은 **전부 순서대로 실행하는 대본이 아니다.** 첫 실행 가능한 패턴에서 생성한 명령 후보 중 하나를 무작위 선택한다. 여러 행동과 여러 대상이 있으면 행동만 균등하게 뽑는 것과 확률이 다를 수 있다.
- `CallEntity.Name`은 `BattleActions.Name`을 찾아 실제 행동을 가져오는 참조다. 새 이야기 장면으로 이동한다는 뜻이 아니다.
- `CallEnemy.EnemyName`은 추가할 적 정의를 가리킨다. 현재 아군 측 개체 수와 `MaxEnemyCount`로 실행 가능 여부를 제한한다.
- 상태의 코드도 DB 패턴을 호출한다. 예를 들어 `ActionPatternHelper`가 사용하는 내부 함정 정의와 군중 패턴은 일반 던전의 무작위 함정 풀에 직접 들어 있지 않아도 사용될 수 있다.

### 탐험과 다음 탐험을 잇는 것은 주로 영구 상태

```text
전투/함정의 효과 → 상태 획득·레벨 변화
                      ├─ 같은 탐험의 행동 조건 변경
                      ├─ 거점 진입 시 분기 조건 변경
                      └─ 영구 상태로 남음
                            → 다음 탐험의 시작 효과·사건 확률 변경
```

확인 예시:

- `誘引洗脳`: 다음 탐험에서도 적/함정 우선 발생 확률에 영향을 준다.
- `常時発情`: 탐험 시작 때 특정 일반 상태를 다시 부여한다.
- `装備定着`: 해당 장비 상태를 탐험 시작 때 다시 부여한다.

즉 사건 A의 완료 플래그가 사건 B를 직접 여는 것보다는, **A의 결과로 남은 상태가 B의 조건을 만족시키는 간접 연결**이 주요 구조다. 개별 상태 모두의 획득·해제·레벨 분기까지 완전한 그래프로 펼친 것은 아니다.

## 6. 문구 데이터와 이야기 이벤트를 구분해야 함

```text
행동 정의 → HMotionSetNames → HMotionSets → HMotions
                                      ↓
                       현재 가능한 대상·행동 요소 선택
                                      ↓
                   행동 메시지 조립 → ReplaceTexts 치환 → 로그
```

`HMotions`는 본문 텍스트뿐 아니라 대상 부위와 피해 수치도 가진 행동 요소다. `HMotionSets` 119행, `HMotions` 614행이 있다고 **독립된 이야기 이벤트가 614개인 것은 아니다.** 같은 사건에서도 가능한 행동 요소와 치환 문구가 달라져 로그가 달라질 수 있다.

## 7. DB 연결 검사 결과와 읽는 법

- SQLite `quick_check`: `ok`; `foreign_key_check`: 위반 없음.
- 적 50행 + 함정 72행 + 전투 행동 250행 = XML 372행 파싱 성공.
- 행동 패턴 392개, `CallEntity` 참조 발생 214개, `CallEnemy` 발생 12개 확인.
- 위 행동/소환 이름 참조에서 대상 누락 없음. 모든 상태 이름·문구 참조·실행 경로까지 검증한 것은 아니다.
- 현재 여섯 던전에 직접 등록된 함정은 중복 제거 시 **27종**. 전체 함정 72종과 구분해야 한다.
- 연결 테이블에는 던전/대상 연결이 NULL인 행도 있다. `DungeonEnemyGroups` 111행 전체를 현재 던전의 등장 그룹 수로 계산하면 안 된다. 실제 여섯 던전 연결은 36행이며, 함정 연결은 전체 76행 중 46행이다.
- 직접 등록되지 않은 나머지 함정 정의를 모두 미사용이라고 단정할 수 없다. 상태 처리·거점·커스텀 경로가 별도로 있다.

## 9. 이 지도를 활용할 때

현재 구조를 논의할 때는 **① 구역 해금 ② 탐험 사건 ③ 전투/함정 내부 패턴 ④ 상태 연결 ⑤ 거점 분기**를 별개 층으로 다루는 것이 정확하다. 기존 사건을 연결해 새로운 연속 퀘스트가 이미 있는 것처럼 해석하지 않는다.

이번 산출물은 조사 보고서와 비서술형 연결 데이터이며 게임 개조물이 아니다. 향후 실제 수정·이식·배포는 설명서의 이용 조건과 권리자 허락을 별도로 확인해야 한다.
