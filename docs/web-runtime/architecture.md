# 구조와 주요 결정

[설계 개요](README.md) · [계약](contracts.md) · [검증 계획](validation-plan.md)

## 1. 계층

```text
Safari / 홈 화면 PWA
  Shell: 라이브러리 · 파일 가져오기 · 플레이 화면 · 백업 · 진단
    RuntimeHost: 엔진 선택 · 세션 상태 · 입력 중계 · 권한/버전 검사
      Trusted EngineRegistry ── engine adapter + JS/WASM (Web Worker)
      PackageService ── importer + 읽기 전용 가상 파일 시스템
      SaveService ── 슬롯/GLOBAL/설정/체크포인트 트랜잭션
      Renderer ── 검증된 텍스트/선택지 이벤트 (추후 별도 Canvas 렌더러)
    IndexedDB: 패키지 메타데이터/바이트 · 세이브 · 마이그레이션 상태
    Service Worker + Cache Storage: 실행기 · 등록된 엔진 빌드
```

- **Shell**: Emuera 변수를 모른다. 접근성, 파일 선택, 일반적인 세션 상태를 표현한다.
- **RuntimeHost**: 한 번에 한 게임을 실행한다. 실행 중인 게임 변경은 저장 여부 확인 → 종료 → 새 세션 생성. 등록된 엔진만 선택한다.
- **Adapter**: 게임 포맷/명령어/이벤트/숫자/세이브 의미를 소유한다. 동기식 게임 입력과 파일 I/O는 비동기 호스트 호출에서 VM을 안전하게 중단·재개한다. SharedArrayBuffer/Atomics 대기를 필수로 하지 않는다.
- **Importer**: 파일 검사와 메타데이터 생성 담당. 게임 로직을 실행하지 않는다. 자동 감지는 제안일 뿐, 불명확하면 사용자가 프로필과 인코딩을 확인한다.
- **Renderer**: 엔진의 출력 이벤트를 렌더링한다. 게임 스크립트를 DOM에 삽입하거나 HTML로 평가하지 않는다. 고정 폭 열 정렬과 모바일 줄바꿈을 별도로 표현한다.
- **Storage**: 세션으로부터 호스트가 도출한 저장 네임스페이스만 제공한다. 엔진 호출 인자로 다른 게임 ID를 받지 않는다.

### 확장 절차

1. 신뢰 가능한 엔진 소스/라이선스, 브라우저 지원과 빌드 재현성을 조사한다.
2. 엔진 descriptor, importer, Worker adapter, 적합성 테스트를 추가한다.
3. 같은 공통 메시지/저장 계약으로 실행한다. 게임별 `if (gameId === ...)`를 Shell에 추가하지 않는다.
4. 새 화면 기능은 renderer capability로 버전 관리한다. 텍스트 엔진에 Canvas/오디오를 강제로 요구하지 않는다.
5. 새 엔진 또는 패키지가 없는 기능을 필수 요청하면 실행 전에 거절한다.

JS 웹앱이나 임의 플러그인 실행은 초기 기능이 아니다. 향후 지원하려면 별도 origin/iframe 격리, 최소 권한 메시지 브리지, 스토리지/네트워크 위협 모델을 새로 설계한다. Web Worker 자체를 악성 JS의 보안 샌드박스로 간주하지 않는다.

## 2. 기술 선택 (구현 시 채택할 기본안)

| 부분 | 기본안 | 이유/경계 |
| --- | --- | --- |
| UI | TypeScript + Vite + React | 엔진에 의존하지 않는 모바일 화면. 아직 의존성 설치/코드 생성 안 함 |
| VM | 전용 Web Worker, 필요 시 WASM | 파싱/실행을 UI 스레드에서 분리. WASM 채택은 엔진 조사 후 결정 |
| 통신 | 구조화 복제 가능한 명시적 버전 메시지 | 함수/DOM 객체 전달 금지, 런타임 스키마 검사 |
| 패키지/세이브 | IndexedDB와 Blob/chunk | iPhone에서 파일 앱 가져오기 기반. localStorage는 대용량 저장에 쓰지 않음 |
| 오프라인 | Service Worker + Cache Storage | 실행기/엔진 캐시와 개인 데이터를 분리 |
| 테스트 | 단위 + 브라우저 자동화 + 실제 iPhone | 데스크톱 WebKit/Chromium 성공만으로 iOS 지원을 선언하지 않음 |

제안 코드 경계는 `web/src/{shell,runtime,packages,storage,renderers,engines}` 및 `web/tests`이다. 현재는 해당 구현 폴더를 만들지 않는다. 엔진 빌드 파일은 앱 릴리스에 고정하여 외부 CDN 장애 없이 캐시 가능하게 한다.

## 3. 가져오기와 데이터 수명

`선택 → 임시 영역 → ZIP 안전 검사 → 파일 인덱스/해시 → 엔진 포맷 감지 → 인코딩 확인 → 엔진 probe → 설치 커밋`

- iOS의 디렉터리 선택, 임의 로컬 경로 접근, File System Access API 쓰기 핸들을 필수로 하지 않는다. 기본 입력은 ZIP 파일이다.
- 상위 래퍼 폴더는 유일한 게임 루트가 검출될 때만 제거한다. 여러 후보면 선택을 요구한다.
- ZIP의 원본 파일 바이트를 보존한다. 실제 텍스트 디코딩은 엔진 VFS에서 한다. 경로의 원래 표기도 진단용으로 보존한다.
- 인코딩은 BOM/유효성 검사로 제안하되 추측 결과를 확정하지 않는다. 파일별 override와 샘플 미리보기 제공. UTF-8, Shift_JIS, EUC-KR 계열 및 CP949 확장 처리 가능 여부를 fixture로 확인한다.
- 가져오기를 취소하거나 용량 부족/검사 실패가 발생하면 임시 데이터만 지운다. 완료 마커 전에는 라이브러리에 실행 가능 상태로 노출하지 않는다.
- 이미 실행 중인 패키지는 수정 불가. 동일 gameId라도 새 내용은 새 package revision으로 등록한다.
- 삭제 UI는 `게임 파일만 삭제(저장 유지)`와 `백업 후 전체 삭제`를 구분한다. 엔진 캐시는 참조 중이면 제거하지 않는다.

## 4. iPhone 플레이 화면

- 세로 화면 우선, safe-area 반영, 동적 viewport/키보드에 대응한다. 가로 전환 시 세션 재시작 금지.
- 선택지는 최소 44 CSS px 터치 영역을 목표로 한다. 키보드 숫자 입력과 동일한 입력 토큰으로 보낸다.
- 한국어 IME 조합 중 Enter는 제출하지 않는다. 입력 버튼 중복 탭과 이전 화면 선택지 재전송을 차단한다.
- 일반 문장은 줄바꿈, 표/고정 폭 출력은 수평 스크롤 가능한 블록. 임의로 줄을 합쳐 명령 의미를 바꾸지 않는다.
- `REUSELASTLINE` 등은 로그 마지막 줄을 식별해 교체한다. 출력 폭/색/정렬/선택지 메타데이터는 adapter가 제공한다.
- 로그는 가상화/상한 설정을 사용한다. 화면 밖 선택지는 현재 입력 requestId와 일치할 때만 유효하다.
- 글자 확대, 대비, 외부 키보드, 접근성 이름, 스크롤 위치와 자동 스크롤 중단을 지원한다.
- 백그라운드 진입 시 안전 지점 저장을 요청하되 완료를 보장하지 않는다. unload 직전 저장에만 의존하지 않는다. 화면에 마지막 **커밋 완료** 시각을 표시한다.
- 체크포인트 미지원 엔진은 마지막 게임 저장으로 복귀한다고 명시한다. 브라우저 종료 후 정확한 명령 위치 복원을 약속하지 않는다.

## 5. 오프라인과 업데이트

`미준비 → 다운로드/가져오기 중 → 검증 중 → 준비됨` 상태를 저장하고 실행 때 재검증한다.

준비 조건은 (a) SW 제어/실행기 자산 완비 (b) 정확한 엔진 빌드/WASM/필수 폰트 완비 (c) 게임 인덱스와 전체 바이트 검증 (d) 저장 쓰기/읽기 probe 성공이다. 단순히 navigator.onLine 또는 홈 화면 아이콘만 보고 판단하지 않는다.

- HTTPS 정적 배포, manifest/icons, scope/base path를 함께 설계한다. 서브경로 호스팅에서도 동작하게 한다.
- 웹 앱 manifest, 개인 게임 manifest, 세이브 backup manifest는 서로 다른 형식이다.
- 개인 게임/세이브는 SW의 공개 asset URL로 제공하지 않는다. 서버·Cache Storage에 게임 업로드를 하지 않는다.
- `navigator.storage.estimate()`로 여유 공간을 안내하고 persistence 요청은 지원될 때만 사용한다. 승인/영구 보존을 가정하지 않는다. 사생활 보호 모드/저장 차단은 경고한다.
- 업데이트는 새 immutable cache에 모두 다운로드/해시 확인 후 대기한다. 실행 중 강제 새로고침/skipWaiting을 하지 않는다.
- 사용자가 세션 종료 후 승인하면 새 실행기로 전환한다. 다른 탭이 실행 중이면 전환을 미룬다. 최소 이전 정상 빌드를 남겨 복구 가능하게 한다.
- DB 마이그레이션은 버전과 저널을 기록한다. 파괴적 변경 전 백업, 실패 시 이전 데이터 유지. 이전 앱이 새 DB를 읽지 못하면 무리한 롤백 대신 복구 화면/내보내기를 제공한다.
- 출처(origin) 변경은 저장 이전으로 간주한다. 이전 주소의 백업 → 새 주소의 가져오기를 안내하며 자동 공유를 약속하지 않는다.

## 6. 보안·권리

- 패키지는 신뢰하지 않는 데이터다. ZIP 경로 traversal, 절대 경로, 드라이브/UNC 경로, NUL, symlink, 중복/대소문자 충돌, 암호화 ZIP, 잘못된 크기/CRC를 거절한다. 중첩 ZIP을 자동 재귀 해제하지 않는다.
- 제안 초기 제한: 압축 100 MiB, 해제 합계 300 MiB, 단일 파일 32 MiB, 항목 20,000개, 압축비 200:1. 플랫폼 한계가 아니라 조정 가능한 제품 기본값이며 실제 게임/기기 측정 후 확정한다. 헤더를 믿지 않고 실제 해제 바이트를 누적 검사한다.
- ZIP 파일명 인코딩/정규화가 모호하면 명시 확인 또는 거절한다. 충돌을 임의로 덮어쓰지 않는다.
- 가져온 EXE/DLL/JS/WASM/HTML은 호스트 코드로 실행하지 않는다. Emuera importer는 데이터 허용 목록을 만들며 그 외 파일은 격리/제외 목록으로 사용자에게 알린다. 다른 엔진의 파일 허용 규칙은 해당 importer가 선언한다.
- 레지스트리 엔진은 소스/의존성/라이선스를 검토한 자사 번들만 허용한다. 패키지가 엔진 다운로드 URL이나 스크립트 URL을 지정할 수 없다. 해시는 무결성이지 저작자 인증이 아니다.
- 게임 명령의 네트워크/OS 실행/임의 경로 접근은 기본 거절한다. 알려진 미지원 명령은 정적 검사에서, 동적 호출은 런타임에서 명시 오류로 중단한다. 조용히 no-op 처리하지 않는다.
- CSP는 inline/eval/외부 연결을 기본 금지하고 WASM 컴파일에 필요한 정책만 지원 브라우저별 검증 후 열어준다. 필요한 same-origin 자산 요청만 허용한다. Worker에도 적용되는 정책을 설정한다.
- CPU 폭주에는 heartbeat/watchdog/Worker 종료, 메모리·출력·메시지에는 상한과 backpressure를 둔다. Worker 종료는 마지막 커밋 저장에 영향을 주지 않는다.
- 사용자 백업의 JSON/경로/크기/해시도 검증한다. 가져온 HTML 문자열은 textContent에 해당하는 안전한 렌더링만 사용한다.
- 오류 보고는 로컬에 파일 경로/행 번호/엔진 빌드/오류 코드만 기본 보관한다. 게임 본문과 세이브는 명시 동의 없이 진단 내보내기에 포함하지 않는다.
- 원본 권리 안내를 변경하지 않는다. 일부 파일의 퍼블릭 도메인 주석을 전체 게임/런처 허가로 확대 해석하지 않는다. 로컬 가져오기가 모든 권리 문제를 자동 해결한다는 뜻도 아니다. 공개 배포에 앞서 실행기·엔진·폰트·샘플별 라이선스를 확인한다.

## 7. 초기 비목표

범용 OS 에뮬레이터, 앱스토어/인증서 설치, 계정·클라우드 동기화, 공개 게임 배포장, 임의 플러그인 마켓, 여러 게임 동시 실행, PC 세이브 무조건 호환, 백그라운드 무중단 실행은 제외한다. 확장 지점은 남기되 검증되지 않은 기능을 지원됨으로 표시하지 않는다.
