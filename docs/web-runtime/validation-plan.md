# 단계별 구현·검증 계획

[개요](README.md) · [구조](architecture.md) · [계약](contracts.md)

이 문서는 단계별 **합격 기준**이다. 문서/진단 테스트 통과와 실제 게임 호환 성공을 구분한다. 현재는 Worker 기반 실제 게임 데스크톱 브라우저 시험이 최소 저장·로드 경로를 통과했지만, 제품 실행기나 공개 배포 URL은 없다. [P0 조사·시험 결과](engine-evaluation.md)를 별도로 기록했다. 큰 정수·전체 명령/KR 확장·iPhone 검증이 남아 전체 P0는 아직 미통과다.

## P0 — 엔진 타당성 (최우선, 전체 구현 전 관문)

작업:

1. 공개 Emuera 호환 웹 엔진/이식 가능한 소스를 조사하고 URL, 커밋, 라이선스, JS/WASM 빌드 절차, KR 확장 여부를 근거와 함께 후보표로 남긴다. 후보 클론/조사, eraJS release JS 재번들 및 독립 fixture 실행까지 수행했으며 제품 엔진 선정은 보류했다.
2. 설치된 Windows EXE를 개조/재배포하지 않는다. 권리가 확인된 후보 소스 또는 독립 구현 가능성을 검토한다.
3. 전체 ERB/ERH/CSV 인벤토리, 전처리, 동적 호출, 설정 우선순위, 인코딩을 조사한다. 명령 이름 검색만으로 실행 호환을 판단하지 않는다.
4. 재배포 가능한 작은 독립 fixture로 출력/입력/정수/문자열/저장을 검증하고 실제 게임 타이틀 → 새 게임 → 첫 정상 입력 → 수동 저장 → 새 세션 로드를 시도한다.

합격: 소스/라이선스 근거와 재현 가능한 빌드, 브라우저에서 입력 대기 가능한 엔진 증거, 필수 명령 지원표 및 실제 게임 최소 경로 기록. 초기 최소 경로 성공은 전체 게임 완주 호환 인증이 아니다.

실패 시: 미지원 명령/기능/권리 문제와 수정 범위를 산출한다. 적용 가능한 엔진이 없으면 별도 VM 이식 프로젝트로 재산정한다. 가짜 선택지 UI를 게임 구동 완료로 보고하지 않는다.

## P1 — 공통 실행기 골격과 확장성 시험

P0가 막히면 제품 전체 구현을 확정하지 않는다. 공통 계약을 시험할 작은 모의 엔진은 독립적으로 만들 수 있다.

작업: UI/라이브러리, Worker Host, registry, 패키지 인덱스, 메시지 검사, 저장소를 구현한다. Emuera 문법 없는 mock-text와 다른 기능 조합의 mock-counter 두 adapter를 만든다. 라이브러리에서 동일 엔진 게임 A/B도 등록한다.

합격:

- 새 게임 추가는 패키지 등록만으로, 새 mock 엔진 추가는 descriptor/adapter/fixture 추가만으로 가능. Shell/SaveService에 게임별 분기 불필요.
- A/B 같은 gameId 또는 같은 슬롯 번호라도 저장/GLOBAL/설정이 섞이지 않는다.
- 알려지지 않은 엔진/API/capability, 잘못된 메시지, stale requestId, 중복 탭은 명시 거절.
- Worker 폭주를 종료해도 Shell과 마지막 저장이 정상이다.
- mock 시험 통과를 Emuera 호환으로 표시하지 않는다.

## P2 — Emuera adapter 및 정확성

필수 시험 영역:

| 영역 | fixture/확인 |
| --- | --- |
| 파일/인코딩 | UTF-8 BOM/무BOM, Shift_JIS, 한국어 확장 문자, 혼합 인코딩, 한글 ZIP 경로, 대소문자 충돌, 파일명 정렬 |
| 파서/전처리 | ERH #DEFINE, 한국어 식별자, 함수/이벤트, 배열/문자열, 동적 호출과 잘못된 명령의 파일·행 오류 |
| 숫자/랜덤 | 53비트 경계, 부호/나눗셈/overflow, 엔진 기준 정수 범위, 고정 seed 테스트 가능성 |
| 출력/입력 | PRINT 계열, 색/정렬/고정 폭, REUSELASTLINE, 숫자/선택지/계속/문자 입력, 한국어 조사·IME |
| 저장 | CHKDATA 반환 의미, 빈/손상/다른 버전 슬롯, SAVEGLOBAL 독립성, 새 게임/로드 시 GLOBAL 유지 |
| 실제 게임 | 타이틀 → 새 게임 → 대표 메뉴 → 수동 저장 → 엔진 재시작 → 로드, 자동 저장 경로/설정 검증 |

합격: 각 지원 기능에 독립 fixture와 기대 결과가 있고, 허용된 기준 실행 환경 또는 사양과 차이를 기록한다. PC 세이브 호환은 별도 왕복 시험을 통과한 경우에만 활성화한다. 미지원 경로는 실행 전에 또는 정확한 런타임 위치에서 실패해야 한다.

## P3 — 데이터 안전성·보안·업데이트

- 정상/대용량 ZIP, traversal(`../`, 드라이브/UNC), symlink, NUL, case/Unicode 중복, ZIP bomb, 암호화/중첩 ZIP, 잘못된 CRC를 시험한다. 실패 후 기존 패키지/세이브 해시가 같다.
- 패키지 내 JS/WASM/HTML이나 URL이 실행/요청되지 않는다. 스크립트 문자열 출력은 화면 텍스트일 뿐 코드 실행이 아니다.
- 저장 중 용량 부족, 트랜잭션 abort, Worker 종료, 브라우저 종료를 주입한다. 이전 성공 revision을 다시 로드할 수 있고 실패를 저장 성공으로 표시하지 않는다.
- 슬롯+GLOBAL+설정 백업 → 라이브러리 새 설치 → 파일 앱에서 복원 → 상태 비교. backup hash/engine/profile/version 불일치는 원본 보존 후 거절 또는 명시 변환.
- 두 탭 동시 저장, lease 만료 후 늦은 writer, 중복 commit의 revision 충돌을 시험한다.
- 패키지/엔진 업데이트 성공·실패·롤백, 오래된 탭과 새 SW, DB migration 실패, origin 이전 백업 복원을 시험한다.
- 오프라인 준비 중 네트워크를 끊으면 부분 캐시를 `준비됨`으로 표시하지 않는다.

합격: 데이터 손실/교차 접근/실패 은폐 없음. 자동화 테스트 결과와 재현 가능한 실패 주입 로그를 남긴다.

## P4 — 실제 iPhone 무PC 플레이 합격

기기 모델, iOS/Safari 버전, 실행 모드(탭/홈 화면), 여유 공간, 패키지/엔진 빌드를 기록한다. 지원 최소 iOS 버전은 실제 결과 후 확정한다. 최신 안정 버전 및 확보 가능한 한 세대 이전 버전을 우선 시험하며, 확보하지 못한 버전은 미검증으로 표기한다.

1. HTTPS 접속, 홈 화면 추가, 파일 앱 ZIP 가져오기, 한국어 인코딩 미리보기를 기기 자체에서 완료한다.
2. 터치 선택지/숫자/한국어 IME/글자 확대/가로 전환/키보드 표시 중 입력 및 스크롤을 확인한다.
3. 게임을 저장하고 파일 앱에 백업한다. 앱을 종료하고 다시 열어 슬롯/GLOBAL을 복원한다.
4. `오프라인 준비됨` 후 앱을 완전히 닫고 비행기 모드에서 홈 화면 아이콘으로 다시 시작한다. 타이틀 → 플레이 → 저장 → 종료 → 로드가 PC/서버 없이 성공해야 한다.
5. 화면 잠금/백그라운드/OS 메모리 종료 후 재개한다. 지원된 checkpoint 또는 마지막 완료 저장으로 돌아가며 손실 범위를 정직하게 표시한다.
6. 저장 공간 부족, 웹 데이터 삭제 후 백업 복원, Safari와 홈 화면 실행 차이, 업데이트 중 네트워크 끊김을 시험한다.
7. 네트워크 로그로 게임/세이브 업로드와 불필요한 외부 의존성이 없는지 확인한다.

초기 성능 목표(보장값 아님): 준비된 패키지 cold start 10초 이내, 일반 입력 후 화면 응답 p95 200ms 이내, 30분 플레이에서 로그 때문에 메모리가 계속 증가하거나 기기가 종료되지 않음. 기준 기기/게임 경로/파일 크기를 함께 기록하고 실측 후 목표를 조정한다.

합격: 위 체크리스트를 실제 iPhone에서 완료하고 결과를 남긴다. 데스크톱 브라우저 자동화나 홈 화면 아이콘 캡처만으로 합격하지 않는다.

## 이번 설계 산출물의 검증 범위

- 문서 4개와 JSON 예시 1개가 존재한다.
- 상대 문서 링크와 예시 구조/필수 필드/권한/경로가 유효하다.
- 다중 엔진 경계, 게임별 저장 격리, GLOBAL, 악성 패키지, iOS 오프라인/업데이트, 엔진 타당성 관문이 문서에 명시되어 있다.
- 문서 추가 전 원본 파일 1,151개의 경로+SHA-256 집계와 추가 후 집계가 일치한다. 집계는 `docs/`를 제외하고 상대 경로를 `/`로 통일한 `path|SHA256`을 ordinal 정렬, LF로 연결한 UTF-8 바이트의 SHA-256이다.
- 기준 집계: `017cbaf8e24440301e71e395bfc8f49189fccab6948c72b517b330898815a37d`.

위 초기 설계 검사는 설계 파일과 원본 보존에 한정된다. 이후 추가한 P0 probe와 브라우저 시험은 원본 1,151개 집계를 실행 전후 재확인한다(`docs/`, `tools/`, `.my_agent_remote/`, `.git/`, `.playwright/` 제외). 실제 게임은 Edge Worker에서 초기 설정·대표 입력·슬롯 저장·페이지 재로드 후 로드를 통과했다. 전체 P0와 P1~P4 제품 구현·iPhone 구동 시험은 완료하지 않았다.
