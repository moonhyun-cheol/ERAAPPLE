# iPhone 시험용 정적 PWA

> 최신 저장 메모리·로컬 진단·최종 회귀는 [자동저장 최적화 보고서](save-memory-optimization.md)를 참고한다. 구 릴리스 `5356ae826c56bb47a372`는 공개 배포했으나 사용자가 약 4일차 종료 재발을 보고했다(실제 적용 ID/직전 진단 미수신). 현재 로컬 릴리스 `788a65fe4ef13e28da14`는 LOCAL 상주 메모리 추가 완화본이며 아직 공개 배포하지 않았다. 아래 자동 시험 결과는 데스크톱 브라우저 기준이며 실기기 해결을 뜻하지 않는다.

[설계 개요](README.md) · [도구 재현](../../tools/web-engine-probe/README.md) · [엔진 한계](engine-evaluation.md)

## 현재 가능한 것

실제 게임과 후보 엔진을 정적 파일로 묶었다. 서버는 최초 다운로드/업데이트용 파일만 제공하고, 게임 연산은 브라우저 Worker, 저장은 IndexedDB에서 수행한다. 배포 이후 플레이에 개발 PC나 실행 중인 Node 서버를 요구하지 않는 구조다.

**이 문서는 현재 가동 중인 공개 주소나 이번 수정본의 iPhone 실기기 통과를 보증하지 않는다.** 과거 사용자의 실기기 성공 보고와 세이브 백업 기능은 [백업 문서](save-backup.md)에 기록되어 있다. 홈 화면 추가를 지원하는 manifest·PNG 아이콘과 안내는 구현했지만 확장형 제품 실행기가 아니라 단일 게임+eraJS 후보의 호환성 시험본이다.

## 제작과 로컬 확인

엔진 고정 클론 및 npm 설치는 [도구 README](../../tools/web-engine-probe/README.md)를 따른다. 프로젝트 루트에서:

```powershell
npm --prefix tools/web-engine-probe run build:pwa
npm --prefix tools/web-engine-probe run serve:pwa
```

- 출력 폴더: `tools/web-engine-probe/pwa-dist/` **내용 전체**. 루트 게임 폴더나 `dist/`, 엔진 클론, `node_modules`를 호스팅하지 않는다.
- 미리보기 서버는 loopback에만 바인딩하며 실행 시 실제 로컬 주소를 출력한다. `PORT`로 포트, `PWA_BASE`로 하위 경로를 지정할 수 있다(기본 `/iphone-test/`).
- `file://`로 HTML을 여는 방식은 지원하지 않는다. iPhone의 LAN `http://PC주소`도 Service Worker 보안 컨텍스트를 충족하지 않으므로 설치/오프라인 시험 경로가 아니다.
- `pwa-build.json`에는 콘텐츠 기반 릴리스 ID, 자산 SHA-256, 원본 파일 집계와 크기가 있다. 같은 입력은 같은 릴리스 ID가 된다. 패키징 실패 시 기존 출력 폴더를 복구하고 원본 파일은 쓰지 않는다.

현재 출력은 gzip 압축 후 약 **11.2MiB**이며, 게임은 `local-game.bin` 안의 NDJSON이다. Worker가 스트림 해제·행별 파싱하므로 압축 전 약 61MiB 텍스트 전체를 단일 JSON 문자열로 파싱하지 않는다. 파일당 업로드 한도, 총 용량·트래픽·콘텐츠 약관을 확인해야 한다. 최초 캐시 생성·해시 검증·컴파일에는 배포 크기보다 큰 메모리와 저장 여유가 필요하며 iPhone 실측치는 없다.

## HTTPS 배포 조건

1. 게임 데이터의 배포/가공 권리와 [원본 권리 안내](../../NOTICE.md), 포함 엔진·의존 라이브러리 고지, 호스팅 콘텐츠 약관을 먼저 검토한다. **게임 JSON도 게임 전체 텍스트를 포함하므로 비밀 파일이 아니다.** 이번 작업에서는 업로드·공개 저장소 push·외부 호스팅을 하지 않았다.
2. 승인된 HTTPS 정적 호스트의 전용 origin 또는 고정 하위 폴더에 출력 내용만 올린다. HTTPS 인증서는 호스트가 제공하는 일반 웹 인증서로, iOS 프로비저닝 프로파일/앱 서명이 아니다.
3. 폴더 URL은 `/`로 끝나도록 리다이렉트한다. manifest의 `id/start_url/scope`, 자산·Worker·SW URL은 상대 경로다. 하위 경로 자동 시험도 수행했다.
4. `.js`는 JavaScript MIME, `.json`은 JSON, `.webmanifest`는 `application/manifest+json`, PNG는 `image/png`, `local-game.bin`은 `application/octet-stream`으로 제공한다. `.bin`은 이미 gzip된 원시 바이트이므로 별도의 `Content-Encoding: gzip`을 붙이지 않는다. 존재하지 않는 자산을 HTML로 바꾸는 SPA fallback과 HTML/JS 자동 삽입·변형은 끈다. 리다이렉트된 캐시 자산도 설치를 거절한다.
5. `sw.js`와 변경 가능한 같은 이름의 자산은 재검증하도록 `Cache-Control: no-cache`를 설정한다. 별도 CDN 의존성은 없다. SW 범위는 배포 폴더 안으로 제한한다.
6. 가능하면 디렉터리/릴리스 단위로 한 번에 교체한다. 부분 업로드 중에는 새 캐시의 해시 검증이 실패하고 기존 활성 버전은 유지되지만, 최초 방문 사용자의 온라인 실행까지 원자적으로 보장하지는 않는다.
7. **주소(origin)를 바꾸거나 사이트 데이터를 지우면 기존 저장에 접근하지 못할 수 있다.** 먼저 [파일 백업](save-backup.md)을 만들고, Safari 사이트 데이터 삭제를 오류 복구 수단으로 사용하지 않는다.

실제 배포 주소는 호스팅과 권한이 정해지고 업로드가 완료된 뒤에만 제공할 수 있다. 현재 미리보기 주소를 iPhone 설치 링크로 소개하지 않는다.

## iPhone에서의 시험 순서

배포된 실제 HTTPS 주소가 생긴 후 아래를 수행한다.

1. Safari의 일반 모드로 열고 `공유 → 홈 화면에 추가`를 선택한다. 공유 메뉴 구성은 iOS 버전에 따라 다를 수 있다.
2. **홈 화면 아이콘으로 다시 열어** `iPhone 설치 · 오프라인 안내`의 `오프라인 준비 / 업데이트 확인`을 누른다. 대용량 다운로드 중 화면을 유지한다.
3. `오프라인 준비됨`과 릴리스 ID를 확인한다. 이 표시는 **캐시 자산 완비**를 뜻하며 IndexedDB 저장 성공·영구 보존·전체 게임 호환성 인증이 아니다.
4. 실제 게임 시작 → 새 게임 → 기본 모드 → EASY → 추가 기능 없음 → 일반 모드 → 프롤로그 생략 → 한국어 이름 `웹시험` → 상점으로 진행한다. 확인/계속 요청에서는 0 또는 전송을 사용한다.
5. `102 휴식`으로 밤까지 진행하고 `200 저장하기 → 슬롯 0`. 화면에 `저장 완료: save00.sav`가 나온 뒤 종료한다.
6. 홈 화면 앱을 닫고 **비행기 모드 + Wi-Fi 꺼짐**에서 다시 연다. 타이틀 → 불러오기 → 슬롯 0에서 `웹시험(주인)`, `일요일(밤)`과 상점 선택지가 복원되는지 확인한다.
7. 다시 휴식해서 진행하고 슬롯 1에 저장한다. 앱 종료 후 다시 불러오기도 확인한다. 마지막 게임 저장 이후 입력은 자동 복구 대상이 아니다.
8. Safari 탭과 홈 화면 앱의 저장소가 공유된다고 가정하지 않는다. 실제로 사용할 홈 화면 앱에서 처음부터 준비·저장·복원 시험을 한다.

## 캐시·업데이트 동작과 복구 한계

- 사용자가 준비 버튼을 눌러야 최초 SW 설치가 시작된다. 실행기·엔진·게임·아이콘 등 10개 자산을 버전별 캐시에 넣기 전에 SHA-256을 확인한다. 실패한 신규 버전 캐시는 지우며 기존 활성 캐시·IndexedDB를 삭제하지 않는다.
- 새 버전 설치 완료 후에도 `skipWaiting`으로 현재 플레이를 가로채지 않는다. 저장을 마친 뒤 같은 실행기의 **모든 탭/홈 화면 창**을 닫아야 활성화할 수 있다. 페이지 새로고침만으로는 전환을 보장하지 않는다.
- 활성화되면 같은 배포 scope의 이전 캐시만 정리한다. 다른 앱 캐시는 보존한다. **활성화 후 이전 버전으로 롤백하는 UI나 DB 마이그레이션은 없다.** 엔진/저장 포맷을 바꾸는 업데이트는 별도 호환성 검토가 필요하다.
- 재방문·전면 복귀 시 캐시 엔트리의 존재를 다시 확인한다. 누락된 파일을 서버의 새 버전과 섞어 실행하지 않고 503으로 거절한다. 셸이 열리는 상태라면 온라인 준비 버튼으로 현재 버전과 해시가 같은 누락 파일을 복구할 수 있다.
- 셸 자체가 삭제돼 화면이 열리지 않거나, 서버에 현재 버전 파일이 더는 없다면 버튼 복구가 불가능할 수 있다. 독립 복구 화면/이전 릴리스 보관은 미구현이다. **사이트 전체 삭제는 세이브까지 지우므로 권하지 않는다.** 원래 릴리스 파일 재제공 등 개발자 조치가 필요하다.
- iOS의 저장소 정리, 사생활 보호 모드, 용량 부족, 강제 종료는 별도 위험이다. [세이브 파일 백업](save-backup.md)을 주기적으로 만들고 실제 파일이 저장되었는지 확인한다.

| Edge PWA 수명주기 | 중첩 하위 경로, 손상된 첫 설치 롤백, 실패 업데이트의 기존 캐시 보존, 업데이트 대기/창 닫은 후 전환, 누락 아이콘 복구, 다른 앱 캐시 보존, 업데이트 뒤 오프라인 새 페이지·fixture 저장 복원 통과 |
| Windows Playwright WebKit 26 | 실제 게임 서버 종료 후 저장·복원·추가 입력·슬롯 1 저장 통과. 최신 릴리스는 서버 종료 방식의 PWA 설치/업데이트 수명주기도 통과(`pwa-webkit-server-stop.json`). iOS Safari 자체가 아님 |
| WebKit 자동화 오프라인 토글 | `context.setOffline(true)` 뒤 `page.reload: WebKit encountered an internal error`. 이 경로는 **실패**이며 서버 종료 방식 성공으로 실패를 삭제하지 않음. 자동화/플랫폼 차이인지 iOS에서도 재현되는지 확정하지 않음 |
| 원본 무변경 | 기존 1,151개 파일의 SHA-256 집계 유지. 기준 `017cbaf8e24440301e71e395bfc8f49189fccab6948c72b517b330898815a37d` |

결과 파일은 `tools/web-engine-probe/results/pwa-chromium.json`, `pwa-game-chromium-browser-offline.json`, `pwa-game-webkit-server-stop.json`. 성공한 실제 게임 시험에서 page error/외부 요청은 없었다. 새 페이지/페이지 재로드는 OS 강제 종료나 브라우저 프로세스 재시작 시험이 아니다. IME 조합 중 제출 억제도 합성 이벤트 시험이며 실제 가상 키보드 확인을 대체하지 않는다.

WebKit 분리 시험 재현(이미 설치된 브라우저라면 설치 단계 생략):

```powershell
Push-Location tools/web-engine-probe
npx playwright install webkit
Pop-Location
$env:PROBE_BROWSER_ENGINE='webkit'
$env:PROBE_OFFLINE_MODE='server-stop'
npm --prefix tools/web-engine-probe run test:pwa-game
Remove-Item Env:PROBE_BROWSER_ENGINE, Env:PROBE_OFFLINE_MODE
```

## 실기기 합격 체크리스트 — 모두 미확인

- [ ] iPhone 모델/iOS 버전/배포 릴리스 ID 기록
- [ ] Safari 접속, 홈 화면 아이콘/standalone 실행, 홈 화면 앱 안에서 캐시 준비
- [ ] 세로·가로 회전, 노치/safe-area, 텍스트 확대, 터치 선택지, 최신 출력 이동
- [ ] 한국어 가상 키보드 조합/확정, 입력창 가림·확대 여부, 키보드 닫힌 후 화면 회복
- [ ] 실제 게임 최소 경로 및 브라우저 내부 슬롯 0/1 저장 복원
- [ ] 비행기 모드에서 앱 닫기/다시 열기·추가 입력·저장 복원
- [ ] 백그라운드/OS 강제 종료 후 마지막 완료 저장 복원
- [ ] 홈 화면 앱에서 날짜 전환·자동저장 반복 후 재발 여부, 직전 실행 진단 기록 확인
- [ ] 업데이트 다운로드 실패·대기·모든 창 종료 후 새 버전·기존 저장 유지

별도 후속 범위: iPhone 파일 백업/복원 실기기 확인, 제품 게임별 저장 격리·마이그레이션, ZIP 가져오기/게임 라이브러리, 공통 다중 엔진 레지스트리, 큰 정수 결함 수정, 장기 플레이/전체 KR 명령, PC Emuera 세이브 호환. 현재 단일 게임의 파일 백업/복원 및 Web Locks 기반 동시 탭 보호는 구현되어 있다. 공통 제품 설계의 자산/개인 게임 분리는 유지하며 이번 정적 게임 번들 방식은 그 최종 구현이 아니다.
